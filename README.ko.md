# Solar System by Solar Ultra

이 문서는 공개 저장소용 한국어 안내서입니다. 구현에 사용한 원문 프롬프트는 다음 링크에서 확인할 수 있습니다.

[프롬프트 원문 보기](https://gist.github.com/plainOldCode/fb2e3ea48caada23107704628c2a9384)

실제 천문 데이터를 바탕으로 태양부터 명왕성까지를 한 화면에서 살펴보는 Three.js 태양계 시각화입니다. 실제 반지름과 궤도 값은 데이터 모델에 그대로 보관하고, 화면에서는 로그 거리 압축과 가시성 중심의 별도 크기 스케일을 적용합니다.

> 이 프로젝트는 교육용 시각화입니다. 천체의 실제 크기와 화면상 궤도 거리는 동일한 물리 스케일을 사용하지 않으며, 현재 위치도 항법·관측용 정밀 천체력이 아닙니다.

## 기술 구성

- **vinext 1**: Next.js App Router 호환 API를 Vite 위에서 실행하는 애플리케이션 계층
- **Vite 8**: 개발 서버와 TypeScript/React 빌드 파이프라인
- **React 19 + TypeScript 5**: HUD, 제어 패널, 정보 패널과 상태 관리
- **Three.js**: WebGL 장면, 천체, 궤도, 별 배경, 카메라 및 `OrbitControls`
- **requestAnimationFrame**: 프레임률과 독립적인 시뮬레이션 루프

브라우저에서 Three.js가 동작하는 클라이언트 컴포넌트와 천문 데이터·궤도 계산·스케일 계산·시뮬레이션 시계를 분리했습니다. 외부 물리 엔진은 사용하지 않습니다.

## 실행

Node.js `22.13.0` 이상이 필요합니다.

```bash
cd solar-system-by-solar-ultra
npm install
npm run dev
```

터미널에 표시되는 로컬 주소로 접속합니다. 프로덕션 빌드는 다음과 같이 확인할 수 있습니다.

```bash
npm run build
```

빌드된 앱을 로컬에서 실행하려면 다음 명령을 사용합니다.

```bash
npm run start
```

정적 검사 명령은 `npm run lint`입니다.

## 기능 개요

- 태양, 수성부터 해왕성까지의 8개 행성, 왜행성 명왕성과 선별한 주요 위성을 표현합니다.
- 실제 반지름, 궤도 장반경, 이심률, 경사각과 공전 주기를 데이터 모듈에 보관합니다.
- Kepler 방정식을 반복 계산해 타원 궤도상의 위치를 구하고, 누적 시뮬레이션 일수로 공전 속도의 실제 비율을 유지합니다.
- 행성계 전체 보기와 선택 천체 포커스 보기를 제공하며, 선택한 행성계에서는 위성 궤도를 더 넓게 펼칩니다.
- 재생/일시정지, 시간 초기화, `1일·10일·100일·1년 / 초` 배속을 제공합니다.
- 로그·선형·포커스 거리 모드와 가시성 강화·상대 크기·균일 마커 크기 모드를 제공합니다.
- 궤도, 라벨, 위성, 별 배경을 각각 켜거나 끌 수 있습니다.
- 정보 패널은 실제 천문 값과 현재 렌더 단위 값을 나누어 표시합니다.

화면의 색, 재질, 표면 표현은 식별을 돕기 위한 시각적 근사입니다. 실제 색상 관측이나 정밀 표면 지도를 재현하는 목적은 아닙니다.

## 실제 데이터와 렌더 스케일

이 앱은 다음 세 값을 의도적으로 분리합니다.

| 구분 | 단위 | 의미 |
| --- | --- | --- |
| 실제 천문 데이터 | km, AU, 일, 시간, 도 | 소스 데이터에 저장된 물리·궤도 값 |
| 렌더 궤도 거리 | Three.js unit | 전체 태양계를 화면에 배치하기 위한 거리 |
| 렌더 천체 반지름 | Three.js unit | 작은 천체를 식별할 수 있도록 조정한 크기 |

따라서 화면에서 지구 반지름과 지구-태양 거리의 비를 재어 실제 비율을 얻을 수 없습니다. 거리 모드를 바꾸어도 원본 천문 데이터는 바뀌지 않습니다.

### 태양 중심 로그 거리

기본값은 `dMax = 39.5 AU`, `rMin = 16`, `rMax = 190`입니다.

```text
n = ln(1 + d) / ln(1 + dMax)
rLog = rMin + n × (rMax - rMin)
```

`d`는 실제 궤도 장반경(AU), `rLog`는 렌더 거리입니다. `log1p` 압축으로 내행성 사이의 간격을 남기면서 명왕성까지 한 장면에 배치합니다.

### 태양 중심 선형 거리

```text
n = d / dMax
rLinear = rMin + n × (rMax - rMin)
```

선형 모드는 AU 차이를 같은 비율로 배치해 내행성이 태양 근처에 밀집되는 현상을 보여 주는 비교 모드입니다. `rMin` 오프셋과 렌더 단위를 사용하므로 이 모드 역시 km 단위의 1:1 물리 모형은 아닙니다.

### 포커스 거리

선택 천체의 거리 `dFocus`를 렌더 범위 중앙에 놓고, 그 천체와의 거리 차이를 부호 있는 로그 함수로 압축합니다.

```text
delta = d - dFocus
span = max(dFocus, dMax - dFocus)
n = sign(delta) × ln(1 + abs(delta)) / ln(1 + span)
rFocus = center + n × (rMax - rMin) / 2
```

이 모드는 선택한 행성계 주변을 읽기 쉽게 만드는 화면 표현이며 새로운 천문 데이터를 생성하지 않습니다.

### 위성 로컬 로그 거리

위성의 km 단위 거리를 태양계 AU 스케일에 직접 넣지 않고, 각 부모 천체의 로컬 좌표계에서 별도로 변환합니다.

```text
shifted = max(0, dKm - dMinKm)
shiftedMax = max(1, dMaxKm - dMinKm)
n = ln(1 + shifted) / ln(1 + shiftedMax)
rMoon = localMin + n × (localMax - localMin)
```

일반 보기의 `localMin`과 `localMax`는 부모의 렌더 반지름 기준 약 `2.5–9배`, 포커스 보기에서는 `3–13배`입니다. 이 방식은 실제 위성 거리순을 유지하되 작은 위성이 부모 천체 안에 겹치지 않게 합니다.

## 천체 크기 모드

모든 식에서 `q = 실제 반지름 / 지구 반지름(6,371 km)`입니다.

### Enhanced Visibility

기본 모드입니다. 작은 천체에 최소 크기를 보장하고 제곱근으로 크기 차이를 완화합니다.

```text
행성·명왕성: clamp(0.55 + 0.65 × q^0.5, 0.55, 4.0)
위성:        clamp(0.16 + 0.40 × q^0.5, 0.16, 0.75)
태양:        8.0 units
```

### Relative Size

`0.78` 지수를 사용해 Enhanced보다 실제 크기 대비를 더 강하게 남깁니다. 다만 작은 천체의 선택 가능성과 전체 구도를 위해 바닥값과 상한값은 유지합니다.

```text
행성·명왕성: min(6.0, 0.18 + 0.75 × q^0.78)
위성:        min(0.9, 0.08 + 0.52 × q^0.78)
태양:        8.0 units
```

### Uniform Markers

천체를 비슷한 크기의 마커로 보여 주되 실제 크기순이 완전히 사라지지 않도록 작은 로그 변화를 둡니다.

```text
rUniform = 0.72 + 0.40 × ln(1 + radiusKm) / ln(1 + 696,340)
```

세 모드 모두 렌더 반지름만 바꾸며 실제 `radiusKm` 값은 수정하지 않습니다.

## 궤도와 시간 모델

- 기준 epoch는 `J2000` (`2000-01-01 12:00 UTC`)입니다.
- 각 천체의 평균 운동은 `360° / orbitalPeriodDays`로 계산합니다.
- 평균 근점각에서 Newton 반복법으로 Kepler 방정식 `M = E - e sin(E)`을 풉니다.
- 장반경과 이심률로 타원 좌표를 만든 뒤 승교점 경도, 근일점 인수, 경사각을 적용합니다.
- 시뮬레이션 시간은 `frameDeltaSeconds × daysPerSecond`를 누적합니다. 프레임 수에 직접 의존하지 않습니다.
- 백그라운드 탭 복귀 시 큰 시간 점프를 줄이기 위해 한 프레임의 실제 시간 증분을 제한합니다.

행성의 J2000 평균 요소와 위성의 평균 요소를 단순화해 사용합니다. 세차, 섭동, 다체 중력, 행성 질량중심의 흔들림과 실시간 관측 보정은 계산하지 않습니다. 위성의 초기 각도 일부는 장기간 안정적인 화면 구성을 위한 표시 위상이며 정밀 천체력으로 해석하면 안 됩니다.

## 포함 천체

- 항성: 태양
- 행성·왜행성: 수성, 금성, 지구, 화성, 목성, 토성, 천왕성, 해왕성, 명왕성
- 지구: 달
- 화성: 포보스, 데이모스
- 목성: 아말테아, 이오, 유로파, 가니메데, 칼리스토
- 토성: 미마스, 엔셀라두스, 테티스, 디오네, 레아, 타이탄, 히페리온, 이아페투스
- 천왕성: 미란다, 아리엘, 움브리엘, 티타니아, 오베론
- 해왕성: 트리톤, 네레이드
- 명왕성: 카론, 스틱스, 닉스, 케르베로스, 히드라

위성은 모든 발견 천체를 나열하기보다 육안 식별성이 높고 각 행성계를 대표하는 위성, 크기·궤도 거리·역행 또는 불규칙 회전 같은 특징을 보여 주는 위성을 우선했습니다. 아말테아, 히페리온, 네레이드는 각각 목성의 내부 위성, 혼돈 자전 사례, 이심률이 큰 외부 위성 사례를 보강합니다. 정의는 데이터 파일에 있으므로 렌더 엔진을 바꾸지 않고 항목을 추가하거나 뺄 수 있습니다.

## 조작법

### 3D 장면

- 왼쪽 드래그: 카메라 회전
- 휠 또는 트랙패드 스크롤: 확대/축소
- 오른쪽 드래그: 화면 이동
- 천체 클릭: 선택 및 포커스
- `태양계 전체 보기`: 전체 구도로 복귀
- `시점 재설정`: 기본 사선 시점으로 복귀

### 제어 패널

- 재생/일시정지와 시뮬레이션 시간 초기화
- `1일`, `10일`, `100일`, `1년 / 초` 시간 배속
- 로그, 선형, 포커스 거리 표현 선택
- Enhanced, Relative, Uniform 크기 표현 선택
- 궤도, 라벨, 위성, 별 배경 레이어 토글
- 천체 바로가기 목록으로 태양·행성·명왕성 선택

위성은 장면에서 직접 선택할 수 있습니다. 선택 정보 패널에는 실제 반지름·거리·주기·이심률·경사각과 현재 렌더 거리·반지름·활성 스케일이 함께 표시됩니다.

```text
app/
  page.tsx                         # vinext App Router 진입점
  components/
    SolarSystemExperience.tsx      # Three.js 런타임과 React UI 상태 연결

    InfoPanel.tsx                  # 실제 값과 렌더 값 비교

    SolarSystemRuntime.ts          # 장면, 선택, 카메라, 렌더 루프
    data/solarSystemData.ts        # 천체 및 위성 데이터
    math/kepler.ts                 # Kepler 방정식과 3D 궤도 좌표
    math/scales.ts                 # 거리·위성·크기 스케일
    SimulationClock.ts             # 프레임률 독립 시뮬레이션 시간
    config.ts                      # 렌더 및 시뮬레이션 상수
    types.ts                       # 명시적 TypeScript 데이터 모델

```

`db/`, `drizzle.config.ts`, `examples/d1/`은 기반 템플릿의 선택적 D1 예제입니다. 현재 태양계 시각화는 데이터베이스를 요구하지 않습니다.

## 성능 메모

- 렌더러 픽셀 비율을 `min(devicePixelRatio, 2)`로 제한합니다.
- 데스크톱과 모바일의 별 개수를 각각 낮추고, 모바일에서는 더 작은 값을 사용합니다.
- 궤도 선의 BufferGeometry와 재질은 초기화 시 만들고 프레임마다 다시 생성하지 않습니다.
- `requestAnimationFrame` 루프에서는 기존 객체의 위치·회전만 갱신합니다.
- 리사이즈 시 카메라 종횡비와 렌더러 크기를 함께 갱신합니다.
- 컴포넌트 해제 시 애니메이션, 이벤트, 컨트롤, Geometry, Material, Texture와 렌더러 리소스를 정리합니다.
- 외부 텍스처가 없어도 실행되도록 색상과 절차적 표현을 사용합니다.

성능은 GPU, 브라우저, 해상도에 따라 달라집니다. 모바일에서 부담이 크면 별·라벨·위성 레이어를 끄고 크기 모드를 단순화할 수 있습니다.

## 접근성 메모

- 주요 조작은 네이티브 `button`, `select`, `details` 요소이며 토글 상태는 `aria-pressed`로 노출합니다.
- 버튼과 3D 영역에 용도를 설명하는 접근성 이름을 제공합니다.
- 색만으로 실제 값과 렌더 값을 구분하지 않고 DOM 텍스트 정보 패널을 함께 제공합니다.
- 한글 이름과 영문 이름을 함께 표시합니다.
- 천체 바로가기 목록은 포인터 선택의 키보드 대안을 제공합니다. 다만 현재 목록은 태양·행성·명왕성 중심이며 개별 위성 포커스는 3D 장면 선택에 의존합니다.
- Three.js 캔버스 자체는 본질적으로 시각적이고 자유 카메라 조작은 포인터 중심입니다. 완전한 비시각적 천문 데이터 탐색기를 대신하지 않습니다.
- OS에서 `prefers-reduced-motion`이 활성화되어 있으면 시뮬레이션은 일시정지 상태로 시작하고 카메라 전환은 즉시 적용됩니다. 재생 버튼으로 원하는 때 다시 시작할 수 있습니다.

## 알려진 한계

- 천체 크기와 궤도 거리는 동일 비율이 아닙니다.
- 선형 모드는 실제 거리 차이를 비교하기 위한 렌더 모드이지 1:1 km 축척이 아닙니다.
- 현재 장면은 평균/근사 궤도 요소를 사용하는 2체 기반 표현이며 실시간 NASA 천체력 뷰어가 아닙니다.
- 행성·위성 간 섭동, 충돌, 식, 조석 변화, 세차와 너테이션은 모델링하지 않습니다.
- 알려진 모든 위성, 소행성, 혜성과 카이퍼대 천체를 포함하지 않습니다.
- 재질과 색상은 식별 중심의 절차적 표현이며 관측 영상 또는 과학적 표면 지도가 아닙니다.
